빅 오 다시 보기

다섯 정렬 절마다 끝에 「몇 번 비교하나」 표를 붙여 두었습니다. 그 표를 읽는 데 빅 오가 쓰이니, 수업에서 배운 것을 먼저 짧게 정리하고 가겠습니다.

빅 오는 이렇게 만듭니다

세 단계입니다. 순서만 지키면 됩니다.

연산 횟수 → 빅 오
①연산 횟수를 세어 n의 식으로 쓴다3n² + 50n + 200
②최고차항만 남긴다3n²
③계수를 지우고 O( ) 안에 넣는다O(n²)

몇 개 더 해 보면 좀 익숙해질 겁니다.

연습
n(n-1)/2먼저 풀면 n²/2 − n/2 입니다. 최고차항 n²/2 → 계수 1/2을 지우면 O(n²)
3n + 5최고차항 3n → 계수 3을 지우면 O(n)
log2n + 1최고차항 log2n → O(log n) (밑도 지웁니다. 까닭은 아래에)
2n log2n + 4n최고차항 2n log2n → O(n log n)
100n이 없습니다. n이 커져도 100 그대로이므로 O(1)

그런데 정의는 따로 있습니다

앞의 세 단계는 빅 오를 구하는 방법입니다. 정의는 다음과 같습니다.

어떤 상수 c 와 n0 가 있어서
n ≥ n0 인 모든 n 에서 f(n) ≤ c × g(n) 이면
f(n) 은 O(g(n)) 이다

f(n) 은 실제로 세어 본 연산 횟수, g(n) 은 n² 이나 n log n 같은 간단한 식입니다.

말로 풀면 “n이 충분히 커지면 f(n)은 g(n)의 몇 배를 넘지 않는다”는 뜻입니다. 여기서 두 가지가 따라 나옵니다.

첫째, 빅 오는 상한입니다. 이보다 나빠지지는 않는다는 약속이지, 정확히 이만큼 걸린다는 뜻이 아닙니다. 뒤에 나올 병합 정렬에서 “8 × 3 = 24번이 상한”이라고 말하는 것이 바로 이 뜻입니다.

둘째, 앞의 ②③단계가 왜 정당한지가 이 부등식 안에 들어 있습니다.

정의에 들어 있는 두 장치
c
몇 배까지 봐주는가		상수배는 따지지 않겠다는 뜻입니다. 5n이든 100n이든 c를 넉넉히 잡으면 부등식이 성립합니다. 그래서 계수를 지우는 ③단계가 정당해집니다.
n0
어디서부터 보는가		n이 작을 때 벌어지는 일은 따지지 않겠다는 뜻입니다. n이 커지면 묻혀 버리는 낮은 항을 지우는 ②단계가 그래서 정당해집니다.

왜 최고차항만 남기고 계수를 지우나

계수부터 봅시다. 연산 횟수가 5n인 알고리즘에서 n을 2배로 하면 10n ÷ 5n = 2, 곧 2배입니다. 100n이어도 답은 똑같이 2배입니다. 5나 100은 계산에서 약분되어 사라집니다. 무시하는 것이 아니라 답에 나타나지 않는 것입니다.

낮은 항은 n이 커지면 저절로 작아집니다. 3n² + 50n + 200에서 n = 2,000이면 3n²가 전체의 99%가 넘습니다. 나머지를 통째로 지워도 오차가 1%도 안 됩니다. 그래서 최고차항만 남깁니다.

그래서 무엇을 말하려는 것인가

빅 오는 시간이 아닙니다. O(n²)는 “n의 제곱 초가 걸린다”는 뜻이 아니에요. 컴퓨터마다 속도가 다르니 초로는 말할 수 없습니다. 빅 오가 말하는 것은 늘어나는 모양입니다. 그 모양을 몸으로 느끼는 방법이 하나 있습니다.

퀵 정렬O(n log n)같은 이유입니다. 다만 나눔이 한쪽으로 쏠리면 단계가 n개가 되어 O(n²)이 됩니다.

가운데 칸과 오른쪽 칸에서 로그의 밑이 다르게 적혀 있습니다. 잘못 쓴 것이 아닙니다. 가운데는 빅 오 기호라 밑을 적지 않고, 오른쪽은 실제로 세는 횟수라 밑이 2입니다. n = 8이면 단계가 정확히 log28 = 3개입니다. 기호에서 왜 밑을 지우는지는 아래 「왜 log2n 이 아니라 log n 이라고 쓰나」에서 설명합니다.

여기서 세는 것은 초가 아니라 비교 횟수입니다

실제로 걸리는 시간은 (비교 횟수) × (한 번 비교하는 데 걸리는 시간)입니다. 뒤쪽은 컴퓨터마다 다르지만 n이 커져도 변하지 않습니다. 그래서 그 부분을 떼어 내면 앞쪽만 남습니다. 시간을 이야기하면서 횟수를 세는 이유가 이것입니다.

log n 은 무엇인가

“n을 몇 번 반으로 나누면 1이 되는가”입니다. 8 → 4 → 2 → 1 이므로 log28 = 3입니다. 1000은 열 번, 100만은 스무 번이면 1까지 갑니다. n이 1000배 커져도 log는 10만 늘어납니다. 그래서 log가 붙으면 거의 커지지 않습니다.

왜 log2n 이 아니라 log n 이라고 쓰나

반으로 나누니까 밑은 분명히 2입니다. 그런데 O(n log n)이라고 쓸 때는 밑을 적지 않습니다.

밑이 다른 로그끼리는 항상 일정한 배수만큼 차이 납니다. log2n은 log10n의 언제나 3.32배입니다. n이 8이든 100만이든 그 배수는 3.32로 변하지 않습니다.

밑만 다른 로그의 값
n = 8log2n = 3log10n = 0.90  →  3.32배
n = 1,000log2n = 10log10n = 3  →  3.32배
n = 1,000,000log2n = 20log10n = 6  →  3.32배

3.32는 n이 커져도 변하지 않는 상수입니다. 그리고 ③단계에서 상수는 지우기로 했지요. 그래서 밑도 함께 지웁니다. 밑이 2이든 10이든 같은 O(log n)입니다.

다만 실제로 횟수를 셀 때는 밑이 2입니다. 반으로 나누니까요. 그래서 이 자료의 표에서는 log28 = 3처럼 밑을 적었고, 빅 오 기호로 쓸 때만 O(n log n)으로 적습니다.

병합 정렬과 퀵 정렬이 빠른 이유는 하나입니다. 한 단계에서 n개를 훑는 것은 다른 정렬과 같은데, 그 단계가 n번이 아니라 log2n번이기 때문입니다. n = 100만이면 100만 번과 스무 번의 차이입니다.

선택 정렬

남은 부분에서 가장 작은 값을 찾아 맨 앞의 값과 교환합니다. 그다음에는 한 칸 오른쪽으로 옮겨 가며 같은 일을 되풀이합니다. 왼쪽은 자리가 확정된 부분이고, 오른쪽은 아직 확정되지 않은 부분입니다.

의사 코드 — 선택 정렬
  1. ALGORITHM SelectionSort(A[0..n-1])
  2. n ← A의 길이
  3. FOR i ← 0 TO n-2 DO
  4. min ← i
  5. FOR j ← i+1 TO n-1 DO
  6. IF A[j] < A[min] THEN
  7. min ← j
  8. A[i] 와 A[min] 을 교환한다
  9. RETURN A
파이썬으로 옮기면
  1. def selection_sort(A):
  2. n = len(A)
  3. for i in range(n - 1):
  4. m = i
  5. for j in range(i + 1, n):
  6. if A[j] < A[m]:
  7. m = j
  8. A[i], A[m] = A[m], A[i]
  9. return A

의사 코드와 줄이 하나씩 그대로 맞습니다. FOR i ← 0 TO n-2 가 for i in range(n - 1) 이 되는 곳 하나만 짚고 넘어가겠습니다. range(n-1) 은 0부터 n-2까지이므로 같은 말입니다.

어떤 데이터가 들어와도 28번으로 같습니다. 가장 작은 값을 찾으려면 남은 구간을 끝까지 다 봐야 하기 때문입니다. n개일 때는 (n-1)+(n-2)+⋯+1 = n(n-1)/2이고, n이 커지면 n²/2가 되므로 O(n²)입니다.

여덟 개인데 일곱 번이면 끝납니다. 일곱 자리가 정해지면 남은 하나는 저절로 제자리이기 때문입니다.

2회차와 7회차처럼 이미 제자리인 경우에도 비교는 그대로 다 합니다. 남은 것을 전부 보기 전에는 제자리인지 알 수 없으니까요. 어떤 데이터를 넣어도 선택 정렬의 비교 횟수가 같은 이유입니다.

02

버블 정렬

옆자리끼리 비교해 순서가 뒤바뀌어 있으면 교환합니다. 한 회차가 끝나면 가장 큰 값이 맨 뒤로 밀려납니다. 그래서 다음 반복은 한 칸 덜 봐도 됩니다.

의사 코드 — 버블 정렬
  1. ALGORITHM BubbleSort(A[0..n-1])
  2. n ← A의 길이
  3. FOR i ← 0 TO n-2 DO
  4. swapped ← false
  5. FOR j ← 0 TO n-2-i DO
  6. IF A[j] > A[j+1] THEN
  7. A[j] 와 A[j+1] 을 교환한다
  8. swapped ← true
  9. IF swapped = false THEN 멈춘다
  10. RETURN A
파이썬으로 옮기면
  1. def bubble_sort(A):
  2. n = len(A)
  3. for i in range(n - 1):
  4. swapped = False
  5. for j in range(n - 1 - i):
  6. if A[j] > A[j + 1]:
  7. A[j], A[j + 1] = A[j + 1], A[j]
  8. swapped = True
  9. if not swapped:
  10. break
  11. return A

range(n - 1 - i) 는 0부터 n-2-i 까지입니다. 의사 코드의 0 TO n-2-i 와 같습니다.
교환은 A[j], A[j + 1] = A[j + 1], A[j] 한 줄이면 됩니다. 임시 변수가 필요 없습니다.

코드를 한 줄씩 읽으면

반복의 범위는 왜 이렇게 정해졌나
바깥 FORi ← 0 TO n-2한 회차마다 가장 큰 값 하나가 맨 뒤에 확정됩니다. n-1개를 확정하면 남은 하나는 저절로 제자리이므로 n-1회차면 끝납니다.
안쪽 FORj ← 0 TO n-2-i여기가 헷갈리는 곳입니다. 버블 정렬은 A[j] 와 A[j+1] 을 함께 봅니다. j 가 마지막 자리인 n-1 까지 가면 A[n] 을 보게 되어 배열 밖으로 나갑니다. 그래서 한 칸 앞인 n-2 까지만 갑니다. 여기에 더해, 이미 뒤쪽에 확정된 i 칸은 볼 필요가 없으므로 그만큼 더 뺍니다.

03

삽입 정렬

값을 하나 뽑아 손에 들고, 왼쪽의 정렬된 구역에 끼워 넣습니다. 카드를 손에 쥐고 정리하는 것과 같습니다. 앞의 둘과 다른 점이 하나 있습니다 — 자리를 교환하는 것이 아니라, 큰 값들을 한 칸씩 밀어내고 빈자리에 꽂습니다.

의사 코드 — 삽입 정렬
  1. ALGORITHM InsertionSort(A[0..n-1])
  2. n ← A의 길이
  3. FOR i ← 1 TO n-1 DO
  4. key ← A[i]
  5. j ← i - 1
  6. WHILE j >= 0 AND A[j] > key DO
  7. A[j+1] ← A[j]
  8. j ← j - 1
  9. A[j+1] ← key
  10. RETURN A
파이썬으로 옮기면
  1. def insertion_sort(A):
  2. n = len(A)
  3. for i in range(1, n):
  4. key = A[i]
  5. j = i - 1
  6. while j >= 0 and A[j] > key:
  7. A[j + 1] = A[j]
  8. j -= 1
  9. A[j + 1] = key
  10. return A

while j >= 0 and A[j] > key: 에서 왼쪽 조건이 먼저 검사됩니다. 그래서 j 가 -1이 되면 A[j] 를 아예 읽지 않고 빠져나옵니다. 순서를 바꿔 적으면 배열을 벗어납니다.

코드를 한 줄씩 읽으면
1def insertion_sort(A):리스트 A를 받는 함수를 만듭니다.
2n = len(A)리스트의 길이를 n에 담습니다.
3for i in range(1, n):1부터 시작합니다. A[0] 한 칸은 그것만 놓고 보면 이미 정렬된 상태이기 때문입니다.
4key = A[i]뽑아 든 값을 따로 담아 둡니다. 7행에서 이 자리가 덮어써지므로 미리 빼 두지 않으면 값을 잃어버립니다.
5j = i - 1바로 왼쪽 자리부터 봅니다.
6while j >= 0 and A[j] > key:조건이 둘입니다. A[j] > key는 언제 멈출지를, j >= 0은 어디까지 갈 수 있는지를 정합니다.
7A[j + 1] = A[j]값을 한 칸 오른쪽으로 밉니다. 이때 같은 값이 잠깐 두 번 보이지만, 원래 값은 key에 들어 있으니 잃어버리지 않습니다.

10return A정렬된 리스트를 돌려줍니다.
반복의 범위는 왜 이렇게 정해졌나
바깥 FORi ← 1 TO n-10 번부터가 아니라 1 번부터 시작합니다. 맨 앞 한 칸은 그 자체로 정렬된 것으로 보기 때문입니다. 마지막 값까지 모두 끼워 넣어야 하므로 끝은 n-1 입니다.
안쪽 WHILEj >= 0 AND A[j] > key범위가 아니라 조건입니다. j >= 0 은 왼쪽 끝을 넘어가지 않게 막고, A[j] > key 는 알맞은 자리를 만나면 멈추게 합니다. 앞의 두 정렬과 달리, 반복의 횟수가 정해져 있지 않습니다.

가장 작은 값이 들어오면 왼쪽 끝까지 가므로, j >= 0 이 없으면 배열을 벗어나게 됩니다.

정리 — 반복의 범위는 무엇을 보고 정하나
바깥 반복몇 번 되풀이할 것인가한 번 되풀이할 때 값 몇 개의 자리가 확정되는지를 봅니다. 하나씩 확정된다면 n-1 번이면 끝납니다. 마지막 하나는 저절로 제자리이기 때문입니다.
안쪽 반복인덱스가 어디까지 갈 수 있나한 번에 몇 칸을 읽는지를 봅니다. A[j] 하나만 읽으면 마지막 자리까지 가도 되지만, A[j] 와 A[j+1] 을 함께 읽으면 한 칸 앞에서 멈춰야 합니다. 읽는 자리가 배열 밖으로 나가면 안 되니까요.
한 번에 읽는 칸인덱스가 갈 수 있는 끝어디서
A[j] 하나n-1 까지선택 정렬 안쪽
A[j] 와 A[j+1]n-2 까지버블 정렬 안쪽
왼쪽으로 가며 A[j]0 이상삽입 정렬 안쪽

끝을 한 칸이라도 잘못 잡으면 파이썬은 IndexError: list index out of range 를 냅니다. 다만 왼쪽으로 갈 때는 곧바로 걸리지 않습니다. A[-1] 은 오류가 아니라 맨 뒤 값을 가리키기 때문입니다. 엉뚱한 값을 한 번 읽고 나서 한참 뒤에야 터집니다. 삽입 정렬에 j >= 0 을 꼭 적어야 하는 이유입니다.

04

병합 정렬

반으로 나누고, 또 반으로 나눠 하나짜리가 될 때까지 갑니다. 하나짜리는 그 자체로 정렬된 것입니다. 거기서부터 둘씩 짝지어 합치며 올라옵니다. 나눌 때는 아무 생각 없이 반으로 자르고, 일은 합칠 때 합니다.

의사 코드 — 병합 정렬
  1. ALGORITHM MergeSort(A[0..n-1])
  2. IF A의 길이 <= 1 THEN RETURN A
  3. mid ← A의 길이 / 2
  4. left ← MergeSort( 앞의 반 )
  5. right ← MergeSort( 뒤의 반 )
  6. RETURN Merge(left, right)
  8. ALGORITHM Merge(L, R)
  9. out ← 빈 목록
  10. WHILE L 과 R 둘 다 남아 있는 동안 DO
  11. IF L의 맨 앞 <= R의 맨 앞 THEN
  12. L의 맨 앞을 꺼내 out 에 붙인다
  13. ELSE
  14. R의 맨 앞을 꺼내 out 에 붙인다
  15. 남은 것을 그대로 out 뒤에 붙인다
  16. RETURN out
파이썬으로 옮기면
  1. def merge_sort(A):
  2. if len(A) <= 1:
  3. return A
  4. mid = len(A) // 2
  5. left = merge_sort(A[:mid])
  6. right = merge_sort(A[mid:])
  7. return merge(left, right)
  9. def merge(L, R):
  10. out = []
  11. i = j = 0
  12. while i < len(L) and j < len(R):
  13. if L[i] <= R[j]:
  14. out.append(L[i]); i += 1
  15. else:
  16. out.append(R[j]); j += 1
  17. out += L[i:]
  18. out += R[j:]
  19. return out

A[:mid] 와 A[mid:] 가 앞뒤 반쪽입니다. 새 리스트를 만들어 넘깁니다.
마지막 두 줄 out += L[i:] 는 한쪽이 비었을 때 남은 것을 비교 없이 그대로 붙이는 부분입니다.

05

퀵 정렬

기준 하나를 골라 작은 것과 큰 것으로 나눕니다. 그리고 양쪽을 각각 같은 방법으로 정렬한 뒤 그냥 이어 붙입니다. 병합과 정반대입니다 — 퀵은 나눌 때 일하고, 합칠 때는 붙이기만 합니다.

의사 코드 — 퀵 정렬
  1. ALGORITHM QuickSort(A[0..n-1])
  2. IF A의 길이 <= 1 THEN RETURN A
  3. pivot ← A의 가운데 값
  4. less ← pivot 보다 작은 값들
  5. same ← pivot 과 같은 값들
  6. more ← pivot 보다 큰 값들
  7. RETURN QuickSort(less) + same + QuickSort(more)
파이썬으로 옮기면
  1. def quick_sort(A):
  2. if len(A) <= 1:
  3. return A
  4. pivot = A[len(A) // 2]
  5. less, same, more = [], [], []
  6. for v in A:
  7. if v < pivot:
  8. less.append(v)
  9. elif v > pivot:
  10. more.append(v)
  11. else:
  12. same.append(v)
  13. return quick_sort(less) + same + quick_sort(more)

나누는 일은 빈 리스트 셋을 만들고 한 번 훑으며 담는 것이 전부입니다. for v in A 는 자리가 아니라 값을 꺼내 주므로 인덱스가 나오지 않습니다.
5 2 9 1 7 3 8 4 를 넣으면 기준은 7, less = [5, 2, 1, 3, 4] · same = [7] · more = [9, 8] 이 됩니다.

다시 부르는 곳less 와 more 만same 은 다시 부르지 않습니다. 기준과 같은 값들은 이미 제자리를 찾았기 때문입니다. 그래서 부를 때마다 적어도 기준 하나는 빠져 덩이가 반드시 작아집니다. 그러니 아무리 깊이 들어가도 언젠가는 멈춥니다.

퀵 정렬에는 반복의 범위를 정하는 일이 없습니다. 자리를 하나씩 짚어 가며 도는 것이 아니라, 값을 하나씩 꺼내 보며 세 덩이에 담기 때문입니다. 그래서 배열 밖으로 나갈 걱정도 없습니다.
